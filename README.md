# TASK DRIVER

#### Video Demo: <https://youtu.be/TZ3QWLViuGU>

#### Description:

Task Driver is a command-line interface (CLI) work order and task management application built with Python. Designed to streamline operational tracking, it allows users to create, view, monitor, update, and delete service requests and work orders efficiently. The application features persistent local data storage using CSV files, an object-oriented data model, robust error handling for user inputs, and a comprehensive suite of automated unit tests powered by `pytest`.

### Project Structure & File Breakdown

The project is organized into a clean, modular architecture across several core files:

- **`project.py`**: This serves as the main entry point and orchestrator of the application. It runs the interactive `while` loop that displays the main menu, captures and validates user menu selections, and coordinates calls to storage and model functions. It handles the core features: viewing tasks, creating new orders, checking request statuses, closing active tickets with action notes, and deleting obsolete orders.

- **`models.py`**: Contains the object-oriented foundation of the application, specifically the `Ticket` class. This class handles the initialization of individual work order attributes—such as the creator, the requested task description, priority level, and an automated tracking status (`"Open"` or `"Closed"`). It encapsulates object states and actions cleanly.

- **`storage.py`**: Manages data persistence using Python's built-in `csv` module. It features `getfile()`, which reads existing records from `work_order.csv` into memory using `DictReader`, and `savefile()`, which safely writes and updates the current state of the application back to disk using `DictWriter` in overwrite-and-refresh mode to prevent duplicate entries.

- **`test_project.py`**: Contains automated unit tests verifying the correctness of input processing, status output, and core functions. It utilizes `pytest` alongside advanced testing techniques like `monkeypatch` (to simulate user keyboard inputs automatically) and `capsys` (to capture and verify terminal print outputs).

- **`work_order.csv`**: The local persistent data store where all active and closed work orders are saved between sessions.

### Design Choices & Technical Implementation

- **CSV Persistence vs. In-Memory State**: Early iterations faced issues with duplicate rows when appending data. To solve this, the storage architecture was shifted to an overwrite model (`'w'` mode) combined with `DictWriter`, ensuring that every time a task is created, closed, or deleted, the CSV file reflects a clean, synchronized snapshot of the active memory state.

- **Timestamp Formatting**: To keep the interface professional and readable, raw timestamps generated by `datetime.now()` are formatted using `.strftime("%Y-%m-%d %H:%M:%S")` to strip high-precision microseconds before saving and displaying.

- **Testing CLI Interactions**: Testing functions that rely on built-in `input()` or `print()` can be challenging. By leveraging `pytest` with `monkeypatch`, simulated inputs (both single values like menu options and sequential strings like `getInput()`) are fed seamlessly into functions without manual intervention. Similarly, `capsys` was utilized to intercept and assert console printouts for status-checking functions.
